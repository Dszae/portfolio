# Security Audit & Incident Investigation: Executive Summary

**Target System:** Dipesh Sapkota Portfolio (`dipeshsapkota7.com.np`)  
**Repository:** `next-portfolio` (`https://github.com/Dszae/portfolio.git`)  
**Audit Date:** October 20, 2026  
**Auditor Role:** Senior Application Security & Incident Response Lead  
**Audit Mode:** Read-Only Audit & Threat Modeling (No destructive actions performed)

---

## 1. Overall Security Posture & Executive Assessment

The website is a modern full-stack application built with Next.js 16 (Turbopack), React 19, Supabase (PostgreSQL & Storage), Tailwind CSS v4, and an integrated AI agent assistant.

The frontend architecture demonstrates strong adherence to baseline HTTP security standards:
- **Comprehensive Browser Security Headers**: Strong Content Security Policy (CSP), Strict-Transport-Security (HSTS), X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Referrer-Policy, and Permissions-Policy are enforced via `next.config.js`.
- **Pre-rendered Static Pages**: ISR components protect the public presentation layer from SQL injection.
- **Structured LLM Bounding**: The AI assistant utilizes strict Zod schema parsing and rate limiting.

However, the audit identified **two high-critical vulnerabilities** related to authentication fallback secrets and database privilege grants, along with several medium-severity issues in rate limiting, session management, and link sanitization.

## 3. Confirmed vs. Unverified Concerns

### Confirmed Vulnerabilities
1. **Hardcoded Fallback Credentials in Git History**: In commit `3899488`, `lib/adminAuth.js` was introduced with a static fallback password and HMAC secret. Because the repository has a public GitHub remote (`https://github.com/Dszae/portfolio.git`), this fallback is publicly visible in Git history.
2. **Infinite Token Replay**: Tokens generated by `adminAuth.js` are signed strings in the format `admin-${timestamp}.${sigHex}`. The verification routine checks only the HMAC signature and never verifies whether `timestamp` is within the 7-day expiration window. Once forged or captured, a token never expires server-side.
3. **No Login Rate Limiting**: The route `POST /api/admin/auth` performs an unrestricted password comparison on every invocation with no lockout, delay, or IP tracking.

### Unverified / Pending Live Verification
1. **Live Production Environment Variables on Vercel**: If `ADMIN_PASSWORD` and `ADMIN_SESSION_SECRET` are explicitly defined in the Vercel dashboard with strong random values, the fallback code in `lib/adminAuth.js` is not reached during runtime execution. However, if either variable is missing or if preview deployments build without them, the hardcoded fallback is active.
2. **Supabase Production RLS Status**: While `scripts/supabase-schema.sql` contains `GRANT ALL ON ALL TABLES ... TO anon`, whether this SQL script was executed in production with RLS active on all tables requires verification in the Supabase Management Console.

## 4. Immediate Containment & Remediation Actions Required

1. **Rotate Administrative Credentials (Priority 1)**:
   - Ensure `ADMIN_PASSWORD` and `ADMIN_SESSION_SECRET` are explicitly set to new, cryptographically strong values in Vercel project environment variables.
   - Remove the plaintext fallback values from `lib/adminAuth.js` so the application fails closed (refuses to authenticate) if environment variables are absent.
2. **Fix Token Expiration in `lib/adminAuth.js` (Priority 2)**:
   - Parse `timestamp` in `verifyToken` and reject tokens older than 7 days (`604800000ms`).
3. **Add Rate Limiting to Admin Login & Contact Forms (Priority 3)**:
   - Apply a sliding-window rate limiter to `POST /api/admin/auth` (e.g. 5 attempts / 15 min) and `POST /api/contact` (e.g. 5 requests / 10 min).
4. **Sanitize Link Protocols in MarkdownRenderer (Priority 4)**:
   - Validate link URLs to ensure only `http:`, `https:`, `mailto:`, or internal paths starting with `/` are rendered.
5. **Harden Database Grants (Priority 5)**:
   - Revoke `ALL` from `anon` on public tables in Supabase.
